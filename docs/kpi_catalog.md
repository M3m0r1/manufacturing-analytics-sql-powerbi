# Каталог KPI

Усі дані синтетичні. Значення нижче взяті з повного запуску й звірені між Python, SQL і Power BI.

## Загальні правила

1. **Одиниця підрахунку це виріб (`unit_id`)**, а не рядок таблиці. Для вказаних вище показників використовується `COUNT(DISTINCT unit_id)` у SQL і `DISTINCTCOUNT` у DAX.
2. Виріб має **один остаточний статус**: `Good` або `Rejected`. Повторні тести його не змінюють.
3. **Дефект не дорівнює браку.** Виріб із виправленим дефектом лишається `Good`.
4. Перед з'єднанням таблиць різного рівня деталізації їх зводять до спільного грейну (CTE у SQL).
5. Ділення виконується безпечно: `NULLIF(..., 0)` у SQL і `DIVIDE` у DAX.

## Обробка повторних тестів

| Правило | Реалізація |
|---|---|
| Рахуємо вироби, а не спроби | `COUNT(DISTINCT unit_id)` |
| FPY використовує лише першу спробу | `attempt_no = 1 AND result = 'Pass'` |
| Retest Rate рахує вироби з 2+ спробами | `MAX(attempt_no) >= 2` |
| Остаточний статус береться з `units.final_status` | перевіряється через останню спробу (`ROW_NUMBER() OVER (PARTITION BY unit_id ORDER BY attempt_no DESC)`) |
| Максимум спроб | 3 |
| Спроби кожного виробу йдуть підряд | перевірка `COUNT(*) = MAX(attempt_no)` |

## Показники

### K1. Planned Units

| | |
|---|---|
| Формула | сума запланованих придатних виробів |
| Чисельник / знаменник | `SUM(planned_good_units)` / немає |
| Одиниця | шт. |
| Джерело | `production_plan` |
| DAX | `Planned Units` |
| Значення | 164 684 |

План задано в **придатних** виробах, тому порівнювати його з Produced некоректно.

### K2. Produced Units

| | |
|---|---|
| Формула | кількість запущених виробів із остаточним статусом |
| Чисельник / знаменник | `COUNT(DISTINCT unit_id)` / немає |
| Одиниця | шт. |
| Джерело | `units` |
| DAX | `Produced Units` = `COUNTROWS(units)` |
| Значення | 165 885 |

### K3. Good Units

| | |
|---|---|
| Формула | вироби зі статусом Good |
| Чисельник / знаменник | `COUNT(DISTINCT unit_id)` де `final_status = 'Good'` / немає |
| Одиниця | шт. |
| DAX | `Good Units` |
| Значення | 153 881 |

### K4. Plan Achievement %

| | |
|---|---|
| Формула | Good Units / Planned Units × 100 |
| Одиниця | % |
| DAX | `Plan Achievement %` |
| Значення | 93.44% |

Рахується від Good, а не від Produced. Інакше брак «маскував» би недовиконання плану. Якщо Planned = 0, результат порожній, а не 0.

### K5. Variance to Plan

| | |
|---|---|
| Формула | Good Units − Planned Units |
| Одиниця | шт. (мінус означає недовиконання) |
| DAX | `Variance to Plan` |
| Значення | −10 803 |

### K6. Scrap Rate %

| | |
|---|---|
| Формула | Rejected Units / Produced Units × 100 |
| Одиниця | % |
| DAX | `Scrap Rate %` |
| Значення | 7.24% (12 004 / 165 885) |

Це частка **забракованих виробів**, а не частка виробів із дефектами. Тому показник названо Scrap Rate, а не Defect Rate.

### K7. First Pass Yield %

| | |
|---|---|
| Чисельник | вироби, у яких перша спроба тесту Pass |
| Знаменник | вироби, які тестувалися |
| Одиниця | % |
| DAX | `First Pass Yield %` (= `First Pass Units` / `Tested Units`) |
| Значення | 91.35% (144 353 / 158 026) |

Вироби, що пройшли лише з другої спроби, у чисельник не входять.

### K8. Retest Rate %

| | |
|---|---|
| Чисельник | вироби з двома й більше спробами тесту |
| Знаменник | вироби, які тестувалися |
| Одиниця | % |
| DAX | `Retest Rate %` (= `Retested Units` / `Tested Units`) |
| Значення | 8.65% (13 673 / 158 026) |

FPY + Retest Rate не завжди дорівнюють 100%. Якби виріб могли списувати після першої невдачі без повторного тесту, сума була б меншою. У нашій моделі кожен виріб після невдачі йде на ретест, тому сума 100%.

### K9. Downtime Hours

| | |
|---|---|
| Формула | сума тривалості простоїв, поділена на 60 |
| Одиниця | год. |
| Джерело | `downtime_records` |
| DAX | `Downtime Hours` |
| Значення | 941.7 |

Не фільтрується за продуктом (у таблиці немає `product_id`).

### K10. Downtime %

| | |
|---|---|
| Чисельник | хвилини простоїв |
| Знаменник | заплановані робочі хвилини = кількість днів-ліній (628) × 660 хв × 2 зміни |
| Одиниця | % |
| DAX | `Downtime %` |
| Значення | 6.82% загалом, Day 6.14%, Night 7.50% |

### K11. Throughput (штуки на годину)

| | |
|---|---|
| Формула | Good Units / фактичні години роботи (заплановані хвилини мінус простої) |
| Одиниця | шт./год. |
| DAX | `Good Units per Run Hour` |
| Значення | близько 11.95 загалом |

Не використовується для порівняння ліній: вони випускають продукти різної складності, і лінія C (лише HB-200) виглядала б гіршою без реальної причини.

### K12. Cost per Good Unit

| | |
|---|---|
| Чисельник | матеріали + праця + накладні (включно з витратами на забракований випуск) |
| Знаменник | Good Units |
| Одиниця | грн/шт. |
| DAX | `Cost per Good Unit` (= `Total Cost` / `Good Units`) |
| Значення | 726.69 грн |

По продуктах: MS-100 609.36, DS-100 420.77, HB-200 1 815.25, FS-300 836.34. Витрати на брак лягають на придатні вироби. Не розрізається за зміною (у витратах зміни немає).

### K13. Scrap by Stage %

| | |
|---|---|
| Чисельник | Rejected-вироби, списані на етапі X |
| Знаменник | усі Rejected-вироби |
| Одиниця | % |
| Джерело | SQL (запит 5.2); у Power BI показано графіком `Rejected Units` за етапами |

Окремої DAX-міри для частки не створено. Розподіл за етапами: 14.4, 22.3, 8.2, 20.6, 20.7, 8.9, 4.9%.

### K14. Scrap Cost

| | |
|---|---|
| Формула | сума по забракованих виробах: `material_cost_uah × cost_accumulated_pct` етапу списання |
| Одиниця | грн |
| DAX | `Scrap Cost` |
| Значення | 4 128 816 грн |

Враховує лише матеріали, тому це оцінка знизу. Працю й накладні, витрачені на забраковані вироби, не включено. Між SQL і DAX можлива розбіжність на 1 грн через округлення.

## Сценарна оцінка (не факт)

| Показник | Формула | Значення |
|---|---|---|
| Estimated Savings | `Scrap Cost × 0.20` | 825 763 грн |

Частка 20% умовна: це припущення «що, якщо брак зменшити на п'яту частину». Вартість самих заходів не враховано.

## Контроль DAX через SQL

Міри звірено з SQL там, де був зріз для порівняння:

| Міри | Зріз звірки |
|---|---|
| Planned Units, Good Units, Variance to Plan, Plan Achievement % | загалом і за місяцями |
| Tested Units, Test Attempts, First Pass Units, Retested Units, FPY %, Retest Rate % | загалом і за продуктами |
| Scrap Rate %, Downtime Hours, Cost per Good Unit, Estimated Savings, MoM Change % | загалом, а Scrap Rate % і MoM Change % ще й за місяцями |
| Downtime % | за змінами |

Cost per Good Unit за продуктами й Scrap Cost за етапами звірено лише в SQL. Розбіжностей, окрім округлень (до 1 грн у Scrap Cost), не виявлено.
